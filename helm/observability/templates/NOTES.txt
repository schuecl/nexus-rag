Nexus RAG observability backends installed (issue #257).

This chart deployed NO Grafana. It deployed the stores your existing air-gapped
Grafana reads, and vendored the dashboards for you to import.

1. Get the LoadBalancer addresses the external Grafana will connect to.
   These may take a minute to be assigned:

     kubectl get svc -n {{ .Release.Namespace }} \
       -l app.kubernetes.io/instance={{ .Release.Name }} \
       -o custom-columns=NAME:.metadata.name,TYPE:.spec.type,EXTERNAL:.status.loadBalancer.ingress[0].ip

2. Install the datasources in the external Grafana. A provisioning file was
   rendered for you with this install's settings:

     kubectl get configmap -n {{ .Release.Namespace }} {{ include "observability.fullname" . }}-grafana-datasources \
       -o jsonpath='{.data.datasources\.yaml}' > datasources.yaml
{{ if or (not .Values.prometheus.service.loadBalancerIP) (not .Values.loki.service.loadBalancerIP) }}
   NOTE: at least one address was not pre-assigned, so that file contains
   REPLACE_WITH_*_LB_ADDRESS placeholders. Substitute the addresses from step 1
   before copying it to Grafana.
{{ end }}
   Copy it to Grafana's provisioning/datasources/ directory and restart Grafana.

   Do not renumber the uid fields. All 14 dashboards reference the literal uids
   prometheus / loki / tempo / alertmanager / documents-pg, and a mismatch
   imports every panel broken with no error.

3. Import the dashboards. They are files in the chart, not objects in the
   cluster -- import them from your checkout:

     helm/observability/dashboards/*.json      (14 dashboards)
     helm/observability/dashboards/system-flow.svg

   Grafana -> Dashboards -> New -> Import, one file at a time, or point a file
   provider at the directory. See helm/observability/README.md for the
   pre-staged plugin prerequisite -- three dashboards render blank without it.

   The RAG quality dashboard remains empty until sanitized report metrics are
   published. Pushgateway is ClusterIP-only; see helm/observability/README.md
   for the allowed-namespace and controlled port-forward workflows.

4. Turn on tracing in the nexus-rag release. It is off until you do: the app
   services no-op when OTEL_EXPORTER_OTLP_ENDPOINT is unset.
{{- if .Values.otelCollector.enabled }}

     helm upgrade {{ .Values.nexusRag.releaseName }} ./helm/nexus-rag \
       --set observability.tracing.otlpEndpoint=http://{{ include "observability.fullname" . }}-otel-collector.{{ .Release.Namespace }}.svc:{{ .Values.otelCollector.service.httpPort }} \
       --set observability.logFormat=json

   logFormat=json matters as much as the endpoint: Loki's trace_id derived field
   matches a JSON log field, so with the default text format the log-to-trace
   links never appear.
{{- else }}

   otelCollector.enabled is false, so there is no OTLP endpoint to point at.
{{- end }}
