Administration

Portal settings

Requires the rag-admin role. Note what that role does not grant: no document access, no query, no curation — managing the vocabulary a document is tagged from is a different authority from seeing anything tagged with it.

Classification banner

Shown at the top and bottom of every portal page. It states what this system is accredited to hold — a deployment decision, not a per-user one, so the same page carries the same marking for everyone.

The full marking line as your accreditation words it. Leave empty and save to remove the banner — pages then read No label set rather than falling back to UNCLASSIFIED, which is a real marking meaning “reviewed and found releasable”.

CAPCO register colours. An unrecognised value renders neutral rather than guessing — a wrong colour on a marking is worse than no colour.

Portal theme

Applies to everyone. Deliberately not a per-user preference: two people looking at the same classified record should see the same page, and the classification banner's colours in particular must mean the same thing to every viewer.

Themes change the palette only. CAPCO banner colours and the good/degraded/failed status colours are fixed in every theme — they carry meaning, so they are not a matter of taste.

Upload quota

Per-identity admission control (NFR-17, issue #424). Request-rate limiting lives at the ingress by design, and it cannot bound a patient submitter: one compliant file every few seconds stays under any rate limit while still filling storage and the review queue. These two caps bound different things, so neither replaces the other.

Counts queued, processing, embedded and pending_review. Curating or rejecting a document frees capacity again, so this throttles a bulk uploader rather than locking them out. 0 disables this cap.

Counts every document the identity submitted in the window whatever its status, because curation does not free storage -- the original is kept (NFR-12) and purging it is a separate deliberate act. 0 disables this cap.

Branding

The application name and logo shown on the login page, the browser tab, the favicon, and the top-left of every page.

A URL this browser can reach -- not an upload. Left empty, the portal falls back to its default name and icon.

Login page

The button text on the login landing page, and an optional warning banner a visitor must accept or decline before it appears.

Shown as a popup on the login page. Declining sends the visitor to a page stating that acceptance is mandatory, instead of the login button. Leave empty and save to remove the popup entirely.
